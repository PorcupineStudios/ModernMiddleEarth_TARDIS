LOTR Mod Code Map

How the classes in The Lord of the Rings Mod (1.7.10, Update 36.15) depend on each other. The mod has no public source, so this is read from the compiled jar in the RingRealms libs/ folder: an arrow from A to B means A's bytecode references B. Inner classes are folded into their outer class. Each dot is a class, sized by how many other classes use it. Built 2026-11-03.

What matters for RingRealms and the port

LOTRMod is the registry for everything. 1,132 of 2,498 classes reference it, because every block, item and dimension is a static field on it. Anything that wants a LOTR block or item goes through this one class.

Saves live in two classes. LOTRLevelData (336 users) holds world-wide state and hands out LOTRPlayerData (326 users), which keeps alignment, fellowships, waypoints, mini-quests and titles per player. These are the internals RingRealms reads for realms and alignment.

Factions and NPCs are the second hub. LOTRFaction (318) and LOTRAlignmentValues (242) feed nearly every NPC. LOTREntityNPC (311) is the base of the 444 NPC classes, with hiring in LOTRHiredNPCInfo, trades in LOTRTradeEntries and families in LOTRFamilyInfo.

World generation is data in code. 169 biomes extend LOTRBiome, 67 structures extend LOTRWorldGenStructureBase2, and huge tables such as LOTRRecipes, LOTRStructures, LOTRChestContents and LOTRTreeType are among the largest files.
